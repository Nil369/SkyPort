**`SkyPort`** is **designed to run** on real `VPS infrastructure` *with your own domain, HTTPS, and reverse proxy configuration.*

This guide explains how to expose the SkyPort Web UI securely using:

* Caddy
* Nginx
* Apache
* Cloudflare DNS
* Direct VPS IP mapping

The setup is intentionally lightweight and works well even on low-end VPS environments.

---

## Recommended Production Architecture


```bash
Internet
│
├── Domain (skyport_vps.example.com)
│
├── DNS Provider
│   └── A Record -> VPS IP
│
├── Reverse Proxy (Use Any One | Recommended: Caddy)
│   ├── Caddy
│   ├── Nginx
│   └── Apache
│
└── SkyPort Backend
    ├── Web UI
    ├── API
    ├── Docker Integration
    ├── PM2 Integration
    └── Metrics
```

---

### Requirements

Before starting, make sure you have:

* A Linux VPS
* **System Requirements:** VPS must have at least 1 vCPU core and 512 MB RAM. For Docker-based deployments, 2 GB RAM or more is recommended.
* A public server IP
* A domain or subdomain
* ports `80` and `443` open
* SkyPort installed

---

::steps{level="4"}

#### <span class="text-blue-500">Point Domain To Your VPS</span>

Go to your DNS provider and create an `A` record.

Example:

```bash
Type: A
Name: skyport
Value: YOUR_SERVER_IP
TTL: Auto
```

Example domain:

```bash
skyport_vps.example.com
```

After DNS propagation:

```bash [bash]
ping skyport_vps.example.com
```

It should resolve to your VPS IP.

#### <span class="text-blue-500">Start SkyPort Backend</span>

Start the backend server:

```bash [bash]
skyport start
```

Check status:

```bash [bash]
skyport status
```

Example output:

```bash [bash]
SkyPort Backend: RUNNING
PID: 5412
URL: http://localhost:8080
```

#### <span class="text-blue-500">Open The Web UI</span>

You can test locally first:

```bash [bash]
skyport start webui
```

Or manually visit:

```bash
http://SERVER_IP:8080
```

::

## Recommended Reverse Proxy: `Caddy`

SkyPort works best with Caddy because:

* automatic HTTPS
* automatic SSL renewal
* simple configuration
* low maintenance
* lightweight memory usage

---

### Install Caddy

::steps{level="4"}

#### <span class="text-blue-500">Ubuntu / Debian</span>

```bash [bash]
sudo apt update
sudo apt install -y caddy
```

Official installation guide: https://caddyserver.com/docs/install

#### <span class="text-blue-500">Configure the Caddyfile</span>

Edit the Caddy configuration:

```bash [bash]
sudo nano /etc/caddy/Caddyfile
```

Example:

```bash [terminal]
skyport_vps.example.com {

    reverse_proxy localhost:8080

    encode gzip

    header {
        Strict-Transport-Security "max-age=31536000;"
        X-Content-Type-Options "nosniff"
        X-Frame-Options "DENY"
        Referrer-Policy "strict-origin-when-cross-origin"
    }
}
```

#### <span class="text-blue-500">Restart Caddy</span>

```bash [bash]
sudo systemctl restart caddy
```

Check status:

```bash [bash]
sudo systemctl status caddy
```

Now open:

```bash [bash]
https://skyport_vps.example.com
```

Caddy automatically provisions HTTPS certificates.

::

### Nginx Setup

If you prefer Nginx:

::steps{level="4"}

#### <span class="text-blue-500">Install Nginx</span>

```bash [bash]
sudo apt install -y nginx
```

#### <span class="text-blue-500">Create the site configuration</span>

```bash [bash]
sudo nano /etc/nginx/sites-available/skyport
```

Example:

```bash [terminal]
server {
    listen 80;

    server_name skyport_vps.example.com;

    location / {
        proxy_pass http://localhost:8080;

        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

#### <span class="text-blue-500">Enable HTTPS on Nginx</span>

Enable the site:

```bash [bash]
sudo ln -s /etc/nginx/sites-available/skyport /etc/nginx/sites-enabled/
```

Test configuration:

```bash [bash]
sudo nginx -t
```

Restart Nginx:

```bash [bash]
sudo systemctl restart nginx
```

Install Certbot:

```bash [bash]
sudo apt install certbot python3-certbot-nginx
```

Generate SSL certificate:

```bash [bash]
sudo certbot --nginx -d skyport_vps.example.com
```

::

### Apache Setup

If your server already uses Apache:

::steps{level="4"}

#### <span class="text-blue-500">Install Apache</span>

```bash [bash]
sudo apt install apache2
```

#### <span class="text-blue-500">Enable proxy modules</span>

```bash [bash]
sudo a2enmod proxy
sudo a2enmod proxy_http
sudo a2enmod rewrite
sudo a2enmod headers
```

#### <span class="text-blue-500">Create the virtual host</span>

```bash [bash]
sudo nano /etc/apache2/sites-available/skyport.conf
```

Example:

```bash [terminal]
<VirtualHost *:80>

    ServerName skyport_vps.example.com

    ProxyPreserveHost On

    ProxyPass / http://localhost:8080/
    ProxyPassReverse / http://localhost:8080/

    RequestHeader set X-Forwarded-Proto "http"

</VirtualHost>
```

Enable site:

```bash [bash]
sudo a2ensite skyport.conf
```

Restart Apache:

```bash [bash]
sudo systemctl restart apache2
```

::

### Running SkyPort As A Service

For production environments, use a system service.

::steps{level="4"}

#### <span class="text-blue-500">Install the service</span>

```bash [bash]
skyport service install
```

#### <span class="text-blue-500">Start the service</span>

```bash [bash]
skyport service start
```

#### <span class="text-blue-500">Check service status</span>

```bash [bash]
skyport service status
```

::

> This ensures SkyPort automatically starts after VPS reboot.

## Firewall Configuration

```bash [bash]
sudo ufw allow 80
sudo ufw allow 443
```

#### <span class="text-blue-500">Enable the firewall</span>

```bash [bash]
sudo ufw enable
```

# Troubleshooting

## Port Already In Use

Check active processes:

```bash [bash]
sudo lsof -i :8080
```

---

## Reverse Proxy Cannot Connect

Verify backend is running:

```bash [bash]
skyport status
```

---

## HTTPS Not Working

Verify:

* DNS propagation completed
* ports 80/443 are open
* reverse proxy is running
